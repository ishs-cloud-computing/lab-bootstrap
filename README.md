# lab-bootstrap

학교 실습실 Windows PC에 **클라우드 컴퓨팅 실습용 도구**를 한 번에 자동 설치하는 PowerShell 부트스트랩 스크립트.

설치 대상:

| 도구 | 용도 |
|---|---|
| **Git** | 버전 관리 |
| **Git LFS** | Git 대용량 파일 저장소 |
| **AWS CLI v2** | AWS 명령행 도구 |
| **SSM 플러그인** | Session Manager 로 인스턴스 접속 (`aws ssm start-session`) |
| **Helm** | Kubernetes 패키지 매니저 |
| **eksctl** | Amazon EKS 클러스터 생성/관리 CLI |
| **kubectl** | Kubernetes 명령행 도구 |
| **Terraform** | IaC (인프라 코드) |
| **VS Code** | 코드 편집기 |
| **k9s** | Kubernetes 터미널 UI |

여기까지가 모두가 공유하는 기본 설치다. 별칭·자동완성 같은 셸 설정은 [`.bootrc`](#bootrc) 파일 하나로 얹는다.

## 시작하기

### 요구 사항

- [PowerShell 7](https://github.com/PowerShell/PowerShell/releases/latest)

```powershell
# winget으로 설치
winget install --id Microsoft.PowerShell -e --source winget --accept-package-agreements --accept-source-agreements
```

### 설치 — 저장소를 받아서 실행 (권장)

```powershell
git clone https://github.com/ishs-cloud-computing/lab-bootstrap.git
cd lab-bootstrap
pwsh -ExecutionPolicy Bypass -File .\bootstrap.ps1

# 인자를 포함하여 실행
pwsh -ExecutionPolicy Bypass -File .\bootstrap.ps1 -KubectlMinor 1.31
```

git 이 없으면 [ZIP 다운로드](https://github.com/ishs-cloud-computing/lab-bootstrap/archive/refs/heads/main.zip) 후
압축을 풀고 그 폴더에서 실행해도 된다.

이 방법을 권장하는 이유가 셋이다:

- 셸 설정 파일 [`.bootrc`](#bootrc) 가 같이 딸려온다. 원라이너에는 그게 없다.
- 파일로 실행해야 **관리자 권한 자동 승격(UAC)** 이 동작한다. 원라이너는 이미 관리자로 연
  pwsh 가 필요하다.
- 설치 로직(`lib/*.ps1`)이 전부 로컬에 있어 네트워크를 타지 않는다.

### 설치 — 원라이너 (도구만)

```powershell
# 관리자 권한 PowerShell 7 에서 실행
irm https://wsc.zenru.net/bootstrap.ps1 | iex

# 또는 github 주소 사용
irm https://raw.githubusercontent.com/ishs-cloud-computing/lab-bootstrap/main/bootstrap.ps1 | iex
```

`lib/*.ps1` 은 `-BaseUrl` 에서 받아온다. 현재 폴더에 `.bootrc` 가 없으면 셸 설정은 건너뛰고
**도구만** 설치된다.

> 설치 직후에는 새 터미널을 하나 열어야 PATH 와 셸 설정이 반영된다.

## 왜 kubectl만 특별 취급하나?

kubectl 공식 배포 사이트(`dl.k8s.io` / `cdn.dl.k8s.io`)가 **학교 네트워크에서 차단**되어 있다.
winget·Chocolatey 의 kubectl 패키지도 결국 이 사이트에서 받으므로 똑같이 실패한다.

그래서 이 스크립트는 kubectl 만은 **Amazon EKS 가 S3 에 미러링한 동일 바이너리**를 받는다:

```
https://s3.us-west-2.amazonaws.com/amazon-eks/<버전>/<날짜>/bin/windows/amd64/kubectl.exe
```

- AWS 공식 문서 기준 *"binary is identical to the upstream community versions"* — 업스트림과 동일한 바이너리다.
- AWS 실습 환경이라 S3 엔드포인트는 방화벽에서 열려 있을 가능성이 높다.
- 받은 뒤 `kubectl.exe.sha256` 로 **SHA256 무결성 검증**까지 수행한다.

나머지 도구는 **winget 우선 설치 → 실패 시 공식 배포처에서 직접 다운로드** 로 fallback 한다.

## 파라미터

| 파라미터 | 기본값 | 설명 |
|---|---|---|
| `-KubectlMinor` | `1.36` | 설치할 kubectl 마이너 버전. **사용하는 EKS 클러스터 버전에 맞춰** 지정. (지원: 1.30 ~ 1.36) |
| `-InstallDir` | `C:\cloud-tools\bin` | 직접 다운로드한 portable 바이너리 배치 폴더 (시스템 PATH 에 자동 추가) |
| `-NoWinget` | (off) | winget 을 건너뛰고 **모든 도구를 직접 다운로드**로 설치 |
| `-Force` | (off) | 이미 설치돼 있어도 다시 설치 |
| `-BaseUrl` | GitHub raw `main` | `lib/*.ps1` 을 받아올 주소. 로컬에 `lib/` 가 있으면 쓰이지 않는다. 미러/포크에서만 지정 (https 만 허용) |

예시:

```powershell
# EKS 클러스터가 1.31 이면
pwsh -ExecutionPolicy Bypass -File .\bootstrap.ps1 -KubectlMinor 1.31

# winget 이 문제를 일으키면 전부 직접 다운로드로
pwsh -ExecutionPolicy Bypass -File .\bootstrap.ps1 -NoWinget
```

## .bootrc

셸 설정은 `.zshrc` 처럼 **파일 하나**다. 저장소 루트의 [`.bootrc`](.bootrc) 가 그것이고,
기본으로 별칭 `g` / `k` / `tf` 와 terraform 자동완성이 들어 있다.

```powershell
# .bootrc
Set-Alias g  git
Set-Alias k  kubectl
Set-Alias tf terraform
```

**찾는 순서**: 현재 폴더 → `bootstrap.ps1` 이 있는 폴더 → 둘 다 없으면 셸 설정을 건너뛴다.
그러니 저장소 폴더에서 실행하면 그냥 적용된다. 원하는 내용으로 고치고 bootstrap 을 다시 돌리면 된다.

### 어떻게 적용되나

`.bootrc` 는 **설치할 때 실행되지 않는다.** 내용이 pwsh 프로필 안의 마커 블록으로 복사되어,
그 뒤로 **새 pwsh 세션마다** 실행된다. 프로필에서 여러분이 직접 쓴 부분은 그대로 보존된다.

```powershell
# ... 직접 쓴 내용 (보존) ...

# >>> lab-bootstrap begin >>>
# Generated by lab-bootstrap from C:\...\.bootrc. Edits between the markers are lost on the next run.
$LabToolsRoot = 'C:\cloud-tools'
Set-Alias k kubectl
Get-ChildItem "$LabToolsRoot\completion\*.ps1" -ErrorAction SilentlyContinue | ForEach-Object { . $_.FullName }
# <<< lab-bootstrap end <<<

# ... 직접 쓴 내용 (보존) ...
```

- 마커 **바깥**은 건드리지 않는다. **안쪽**은 매 실행 통째로 갈린다.
- 복사 전에 `.bootrc` 를 문법 검사한다. 깨진 파일이 실습실 PC 의 모든 새 터미널에서 에러를
  뿜는 상황을 여기서 `[FAIL]` 한 줄로 막는다.
- 프로필을 고치기 전에 `%TEMP%\lab-bootstrap\profile_*.bak` 으로 백업해 둔다.

### 자동완성

kubectl / helm / eksctl / k9s 의 탭 자동완성은 **설치할 때 파일로 구워** `C:\cloud-tools\completion\`
에 둔다. 생성기를 셸 시작마다 돌리면 도구당 100~300ms 씩 새 터미널이 느려지기 때문이다.

이 파일들은 `.bootrc` **다음에** 로드되고 별칭을 스스로 찾아 붙는다. 그래서 `.bootrc` 에
`Set-Alias k kubectl` 한 줄만 써도 `k get po<TAB>` 이 동작한다. 따로 할 일은 없다.

> 도구를 업그레이드하면 bootstrap 을 다시 실행해야 완성 목록이 새 버전 기준으로 갱신된다.

git 자동완성은 **의도적으로 넣지 않았다.** PowerShell 에서 제대로 하려면 PSGallery 의 `posh-git`
모듈이 필요한데, 실습실 네트워크에 의존성을 하나 더 만들 이유가 없다고 판단했다.

**전부 되돌리려면** → [UNINSTALL.md](UNINSTALL.md)

## 구조

`bootstrap.ps1` 은 로더다. 설치 로직은 `lib/` 에 나눠져 있고, 로컬에 있으면 그걸 쓰고 없으면
`-BaseUrl` 에서 받는다.

| 파일 | 담당 |
|---|---|
| `bootstrap.ps1` | 파라미터, **버전 표와 pin**, 로깅, 모듈 로더, 설치 순서 |
| `lib/env.ps1` | 권한 승격, PATH, ssh-agent |
| `lib/net.ps1` | 다운로드, 압축 해제, 최신 버전 조회 |
| `lib/install.ps1` | 도구 무관 설치 엔진 (winget → 직접 다운로드) |
| `lib/tools.ps1` | 도구별 URL·설치 플래그, kubectl |
| `lib/shell.ps1` | 자동완성 굽기, `.bootrc` → 프로필 |
| `lib/verify.ps1` | 마지막 검증 요약 |

각 `lib/*.ps1` 은 **정의만** 담는다 (최상위 실행 코드 없음). 그래서 로드 순서가 문제되지 않는다.
첫 줄의 `# lab-bootstrap lib 1` 은 형식 표시이자 무결성 검사다 — 캡티브 포털 로그인 페이지나
잘린 응답을 받았을 때 파서 에러 대신 "어디서 받은 무엇이 잘못됐는지"를 말해준다.

## 동작 특성

- **Idempotent**: 이미 설치된 도구는 건너뛴다. 재부팅으로 초기화되는 실습 PC 에서 매 세션 다시 돌려도 안전하고, 재실행이 빠르다.
- **로그**: 전체 실행 로그가 `%TEMP%\lab-bootstrap\bootstrap_<시각>.log` 에 저장된다.
- **PATH**: `-InstallDir` 을 시스템 PATH 에 1회만 추가한다.
- **완성 스크립트**: `C:\cloud-tools\completion\` 는 매 실행 비워지고 다시 구워진다.
  설치돼 있지 않은 도구의 자동완성이 남아 있는 일이 없다.
- **프로필 대상**: `.bootrc` 블록은 공용 프로필(`$PROFILE.AllUsersAllHosts`)에 우선 쓰고,
  거기에 쓸 수 없으면 현재 사용자 프로필(`$PROFILE.CurrentUserAllHosts`,
  `Documents\PowerShell\profile.ps1`)로 넘어간다.
  pwsh 7 을 **Microsoft Store 로 설치한 PC 가 이 경우**다 — `$PSHOME` 이 `C:\Program Files\WindowsApps`
  아래라서 관리자도 쓸 수 없다 (게다가 경로에 버전이 박혀 있어 pwsh 업데이트마다 사라진다).
  이때는 `[WARN]` 과 함께 그 계정에만 적용된다는 사실을 알려준다.
  어느 쪽에 걸렸는지는 `Verify` 의 `.bootrc` 줄에 나온다. 한쪽에 쓰면 다른 쪽에 남아 있던
  블록은 지운다 — 머신당 블록은 항상 하나다.
  사용자 프로필로 넘어간 경우, UAC 승격을 **다른 관리자 계정**으로 넘겼다면 블록은 그 관리자의
  `Documents` 에 들어간다. 이때는 실제로 쓸 계정의 pwsh 에서 bootstrap 을 한 번 더 돌리면 된다
  (실습실은 공용 계정 1개를 쓰므로 해당 없음).

## kubectl 버전 갱신

새 Kubernetes 마이너 버전이 나오면 `bootstrap.ps1` 상단의 `$KubectlMap` 표만 갱신하면 된다.
최신 전체버전/빌드날짜는 [AWS EKS: Install kubectl](https://docs.aws.amazon.com/eks/latest/userguide/install-kubectl.html) 문서에서 확인한다.

```powershell
$KubectlMap = @{
    "1.36" = @{ v = "1.36.2";  d = "2026-06-17" }
    "1.35" = @{ v = "1.35.3";  d = "2026-04-08" }
    ...
}
```

## 버전 pin 갱신

winget 없이 직접 다운로드할 때 스크립트는 각 도구의 최신 버전을 온라인으로 조회한다.
조회가 실패하면 `bootstrap.ps1` 상단의 **pin 값**을 쓴다.

```powershell
$HelmPinned      = "4.2.3"
$TerraformPinned = "1.15.8"
$GitLfsPinned    = "3.7.1"
$GitPinnedUrl    = 'https://github.com/git-for-windows/git/releases/download/v2.55.0.windows.3/Git-2.55.0.3-64-bit.exe'
```

이 pin 은 장식이 아니라 **실습실에서 실제로 자주 쓰인다**: 무인증 GitHub API 는 IP 당 시간당 60 요청이고
실습실 전체가 학교 NAT 주소 하나를 공유하므로, PC 20 대가 동시에 돌리면 쿼터가 소진되어 이후 전부
`403` 이 된다. 그때 pin 이 없으면 그 도구는 설치가 실패한다. 학기 시작 전에 한 번씩 갱신해두면 좋다.

(Git for Windows 는 태그와 파일명의 버전 표기가 달라서 — `v2.55.0.windows.3` vs `Git-2.55.0.3-64-bit.exe` —
버전 대신 URL 전체를 pin 한다.)

## 문제 해결 (FAQ)

**Q. `PowerShell 7+ is required` 오류가 난다.**
Windows 기본 셸(Windows PowerShell 5.1)로 실행한 것이다. `powershell` 이 아니라 **`pwsh`** 로 실행한다.
`pwsh` 명령 자체가 없으면 위 [요구 사항](#요구-사항) 섹션을 먼저 수행한다.

**Q. winget 이 설치돼 있지 않다.**
스크립트 자체는 winget 이 없어도 자동으로 직접 다운로드로 넘어간다.
다만 **선행 조건인 PowerShell 7 설치**가 먼저 막히므로, PowerShell 7 은 MSI 로 직접 설치하거나
Microsoft Store 에서 "앱 설치 관리자(App Installer)" 를 먼저 설치한다.

**Q. kubectl 설치에서 실패한다 (S3 도 막힌 경우).**
드물지만 S3(`amazon-eks`) 까지 차단됐다면, 인터넷 되는 곳에서 위 S3 URL 로 `kubectl.exe` 를 미리 받아
USB 등으로 옮긴 뒤 `-InstallDir`(`C:\cloud-tools\bin`) 에 복사하면 된다.

**Q. `code` / `session-manager-plugin` 명령을 못 찾는다.**
installer 가 PATH 를 등록한 직후라 현재 창에 반영되지 않았을 수 있다. **새 터미널**을 열어 다시 확인한다.

**Q. 실행이 스크립트 실행 정책 때문에 막힌다.**
`pwsh -ExecutionPolicy Bypass -File .\bootstrap.ps1` 로 실행한다 (위 예시 참고).

**Q. `not a lab-bootstrap lib 1 file` / `cannot fetch ...` 로 죽는다.**
`bootstrap.ps1` **한 파일만** 복사해 온 경우가 대부분이다. `lib/` 를 포함해 폴더째 가져온다.
폴더째 가져왔는데도 나면 `-BaseUrl` 이 가리키는 곳이 응답하지 않는 것이다 (학교망 로그인
페이지가 가로채는 경우 포함). 이 검사가 없으면 남의 HTML 을 코드로 실행하게 되므로 일부러 막는다.

**Q. 새 터미널에서 `k` / `tf` 가 안 먹는다.**
1. 실행한 폴더에 `.bootrc` 가 있었는지 확인한다. 없으면 셸 설정은 아예 건너뛴다
   (실행 로그 끝 `Verify` 의 `.bootrc` 줄에 `none` 이라고 나온다).
2. **새 터미널**을 열었는지 확인한다. 이미 열려 있던 창에는 반영되지 않는다.
3. `powershell`(Windows PowerShell 5.1)이 아니라 **`pwsh`** 인지 확인한다.
4. 실제 등록 여부:
   ```powershell
   $PROFILE.AllUsersAllHosts, $PROFILE.CurrentUserAllHosts |
       Where-Object { Test-Path $_ } | Select-String 'lab-bootstrap begin'
   ```

**Q. 별칭은 되는데 `<TAB>` 이 안 먹는다.**
`Get-ChildItem C:\cloud-tools\completion` 에 해당 도구의 `.ps1` 이 있는지 본다.
없으면 로그에서 `[WARN] <도구> completion skipped` 를 찾는다 — 그 도구 버전이 PowerShell 완성
생성기를 지원하지 않는 것이고, 별칭 자체는 그대로 동작한다.
